# IV. Before the interview

## Getting the rigth experience

For students:
    * Take the Big Project Classes: The more relevant the project is to the world, the better
    * Get an intership: Do everything to land an intership early in school
    * Start something: Build a project alone, participate in Hackatons or contribute to open source projects

For Professionals:
    * Shift work responsabilities more towards coding: Try to take a bigger coding challenge, use relevant technologies
    * User Nights and Weekends: Use free time to build a mobile app, a web app, or a piece of desktop software

## Writting a Great Resume

* Appropriate Resume Length
    * Recruiters only spend a fixed amount of time looking at a resume
    * Some people just flat-out-refuse to read long resumes

* Employment History
    * A resume shouldn't include a full history of every role you've ever had. It should content only the relevant positions
    * "Accomplished X by implementing Y which led to z"

* Projects
    * Developing the projects section on a resume is often the best way to present someone as more experienced

* Programming Languages and Software
    * Software: Be conservative about what software is listed
    * Languages: List most of the languages used, but with an experience level

* Potential Stigma
    * Certain languages have a stigma associated with them
    * Being Too Language Focused
    * Certifications: 
    * Knowing only one or two languages
