# S3 basics

* Global Storage Platform, it can be accessed from anywhere
* A regional service and regional resilient. 
* Data can be replicated on the multiple AZ within a region
* Data stored lives strictly in the specific AWS region where the bucket was created. However, the namespace for bucket names is global, and the API endpoints are globally accessible via HTTP/HTTPS
* Public Service, unlimited data and multi-user
* It can store different type files with different sizes
* It's economical and can be accesed via UI/CLI/API/HTTP
* It's an object store (images, videos, text files, audios) - not file (can't be used to search files) or block (can't be mounted as a mount point or a volume)

## Objects

* The data the S3 stores
* Can be thinking as files
* Components:
    * Key: similar to a file name. It identifies the object in the bucket
    * Value: The data or content of the object. How large the object can be range from zero bytes up to five terabytes in size
    * Version ID, Metadata, Access Control and Subresources

## Buckets

* Are container for objects
* Are created in a specific AWS region
* The data inside a bucket never leaves that region, unless is configured
* A bucket is defined by a name, which is globally unique across all regions and all AWS accounts
    * The bucket name should have 3-63 characters, all lowercase, no underscores
    * The bucket name should start with a lowercase letter or a number
    * The bucket name can contain hyphens, as long as they aren't adjacent to periods
    * Can't be IP formatted
* Buckets can hold an unlimited number of objects
* All objects are stored following a flat structure, it isn't like a file system
